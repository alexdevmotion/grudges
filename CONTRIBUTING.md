# Contributing

Use Python 3.11+ and run the development commands in README.md. Keep changes focused and add regression coverage when behavior changes. Never include captured sessions, credentials, private source code or raw provider receipts in a contribution.

A new task needs an explicit interface, a deterministic verifier, a reference solution, and fairness notes separating stated requirements from reasonable inferences. Do not grade later preferences as if the original request stated them. Validate nop failure, oracle success and plausible near misses; inspect each receipt, not just the process exit code. Docker controls do not require provider credits. Live-model validation must be separately budgeted.

Keep task changes versioned and old validation receipts clearly tied to their original inputs. Contribution of a task does not establish broad model quality or customer demand.
